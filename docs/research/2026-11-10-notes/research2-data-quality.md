## 1. Yahoo Finance / yfinance defects

- yfinance README: "not affiliated, endorsed, or vetted by Yahoo"; "intended for research and educational purposes"; says Yahoo API is for personal use only; makes no accuracy claim. (page) https://github.com/ranaroussi/yfinance
- Official docs page for `Ticker.history` on ranaroussi.github.io shows only the signature (no parameter text). (page) https://ranaroussi.github.io/yfinance/reference/api/yfinance.Ticker.history.html
- history() docstring in source (page): `auto_adjust` "Adjust all OHLC automatically?" default True; `back_adjust` default False; `repair` default False; `keepna` default False (NaN rows dropped); `prepost` default False; `actions` default True; "Intraday data cannot extend last 60 days"; 30m is fetched as 15m and resampled (Yahoo API bug workaround); with period="max" intraday defaults are 8 days for 1m, 60 days for 2m/5m/15m/30m/90m, 730 days for 1h. Only first 100,000 chars of the file were read. https://raw.githubusercontent.com/ranaroussi/yfinance/main/yfinance/scrapers/history.py
- Price repair, official docs (page): `repair=True` on history()/download() adds a `Repaired?` column. It fixes (a) missing dividend adjustment in Adj Close (this fix does not set `Repaired?`), (b) missing split adjustment, (c) unexplained split-like adjustments, measured against 1h data (only within the last 2 years), (d) missing or corrupt rows and Volume rebuilt from a smaller interval (for example 1h fixes 1d), (e) 100x currency errors ($/cents, GBP/pence), scattered or in blocks, detected with scipy, (f) dividend errors: wrong/missing adjustment, duplicate within 7 days, 100x too large/small, wrong ex-dividend date, double-counted capital gains. https://ranaroussi.github.io/yfinance/advanced/price_repair.html
- Same docs, caveats (page): "Only US market data appears perfect"; "Most errors I've seen are on London stock exchange" and "no exchange is safe"; reconstructed values may later differ "often significantly" from Yahoo's corrected data; repair can give false positives, mainly with small dividends; only 1d is repaired (longer intervals are fetched daily, repaired, then resampled); 1h data cannot be fetched beyond 2 years; check `history_metadata['currency']` rather than `Ticker.info` for the true currency. https://ranaroussi.github.io/yfinance/advanced/price_repair.html
- The wiki version of the same page names Hong Kong tickers as examples: 0316.HK (missing volume, daily price changed) and 1398.HK (missing dividend adjustment, Adj Close equals Close) (snippet only, via search summary). https://github.com/ranaroussi/yfinance/wiki/Price-repair
- I found no GitHub issue specific to a HK lot-size or HKD unit error. Searches for 0700.HK issues returned nothing specific (search result, unconfirmed absence). Issue #300 (volume incorrect) concerns AAPL/DIS, not HK (snippet only). https://github.com/ranaroussi/yfinance/issues/300
- Changelog entries on repair (page; no dates in the file): 0.2.42 extends repair to dividends and adjustments (#2031); 1.1.0 repair for capital-gains double-counting (#2667); 1.5.1 fixes unit-switch repairs applied twice, false-positive bad dividends, infinite Adj Close; 1.6.0 stops repair permanently converting GBp/ZAc/ILA to main currency (#2907); 1.7.0 volume-validation bug in split repair (#2958); 1.8.0 fixes split-like level shifts without a split using 1h data (#2990). https://github.com/ranaroussi/yfinance/blob/main/CHANGELOG.rst
- Yahoo applies splits itself: issue #2076 (AAPL 4-for-1 shows no price drop with auto_adjust=False); maintainer: "Yahoo auto-apply splits." Closed "not planned" 6 Oct 2024. So `Close` is always split-adjusted, only dividend adjustment is switched by auto_adjust. (page) https://github.com/ranaroussi/yfinance/issues/2076
- How Adj Close is computed (maintainer, issue #2070, page): each dividend's factor is 1.0 minus dividend divided by the prior day's close, factors multiplied together; remaining differences from Yahoo's own total-return figures are "rounding"; Yahoo computes Adj Close in its own table so yfinance cannot explain gaps. Users reported gaps (VDY.TO 2024: 18.19% computed vs 21.42% on Yahoo's page). Issue stayed open. https://github.com/ranaroussi/yfinance/issues/2070
- auto_adjust default for download(): issue #2283 (opened 19 Feb 2025) says Adj Close disappeared from download() output in version 0.2.54; maintainer said default changed for consistency with `Ticker.history`; closed "not planned" 10 May 2025. A secondary comparison page says 0.2.51 (snippet only, conflicting). Changelog says 0.2.53 added a warning when download() is called without auto_adjust (#2230). (page) https://github.com/ranaroussi/yfinance/issues/2283
- Rate limits and breakage (snippet only for the issue contents): crumb value returned as "Edge: Too Many Requests" (#2297, Feb 2025, still failing on 0.2.54); crumb literally "Too Many Requests" (#2441, May 2025); persistent cookie reuse with bad crumb (#2128); still failing on 0.2.57-0.2.59 (#2480). Changelog (page): 0.2.52 raises YfRateLimitError (#2108); 0.2.58/0.2.59/0.2.62 rate-limit fixes; 0.2.62 moved to curl_cffi; 1.0 blocks curl_cffi 0.14; 1.2.1 requires curl_cffi>=0.15 (CVE); 1.4.0 makes curl_cffi optional; 1.5.2 fixes breakage with curl_cffi>=0.16. https://github.com/ranaroussi/yfinance/issues/2297 , https://github.com/ranaroussi/yfinance/issues/2441 , https://github.com/ranaroussi/yfinance/issues/2480
- Missing day across many tickers: issue #2621 reports missing price history for 5 Nov 2025 "prevalent across tickers" (snippet only). https://github.com/ranaroussi/yfinance/issues/2621

## 2. Corporate-action adjustment; HK specifics

General/tool handling:
- Qlib stores prices adjusted by a `factor` field: "factor = adjusted price / original price"; divide by `$factor` to get original close; each stock's first-day price is set to 1; adjusted prices "can differ between data sources"; suspended stocks get NaN. (page) https://qlib.readthedocs.io/en/latest/component/data.html
- Qlib's Yahoo collector README: "We have considered STOCK PRICE ADJUSTMENT, but some price series seem still very abnormal"; scales OHLC by adjclose, then rebases first valid close to 1; "the data might not be perfect"; supports CN, US, IN, BR (HK not mentioned); 1-minute data is only the last month; offline data cannot be updated incrementally. (page) https://github.com/microsoft/qlib/blob/main/scripts/data_collector/yahoo/README.md
- zipline-reloaded bundles: separate writers for assets (AssetDBWriter), daily bars (BcolzDailyBarWriter, each call replaces the whole table) and adjustments (SQLiteAdjustmentWriter: splits, mergers, dividends, stock dividends). Stored-unadjusted is the page's layout implied, not stated. (page) https://zipline.ml4trading.io/bundles.html
- LEAN: default is to adjust US equities for splits and dividends; modes RAW, ADJUSTED, SPLIT_ADJUSTED, TOTAL_RETURN, SCALED_RAW (history only); ADJUSTED uses the full split/dividend history "so adjusted prices don't change with the backtest end date". (page) https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/us-equity/requesting-data . Forum staff: US equity files hold raw data; adjustment uses factor files; map files handle ticker renames and mark delistings by end date (snippet only). https://www.quantconnect.com/forum/discussion/3638/how-to-process-local-that-is-already-split-adjusted/
- Tiingo EOD (page): provides raw and adjusted OHLCV plus `divCash` and `splitFactor`; adjustment "follows the CRSP standard method"; prices have an error-detection framework; exchanges may send corrections until 8 PM EST and prices are updated through the evening. https://www.tiingo.com/documentation/end-of-day
- Norgate: could not open Norgate's own pages (404). Third-party sources say Norgate holds a delisted US archive and historical index membership (snippet only). I found nothing on its adjustment method. (unconfirmed) https://concretumgroup.com/how-to-construct-a-survivorship-bias-free-database-in-norgate-using-python/
- CRSP: no source found for CFACPR/CFACSHR field mechanics. (unconfirmed) Shumway (1997) delisting-return bias is covered in section 3.
- Why back-adjusted history changes: each new dividend rescales every earlier adjusted price by (1 - dividend / prior close) per the maintainer's description in #2070 (page), so a cache of adjusted prices holds values that differ from a fresh download after any later dividend or split. https://github.com/ranaroussi/yfinance/issues/2070 (the cache consequence is my inference from the formula)

## 3. Survivorship bias and universe construction

- Elton, Gruber, Blake (1996), Review of Financial Studies 9:1097-1120, follows funds existing at end of 1976 and computes merged funds' returns from merger terms. The abstract on NYU's archive gives no numeric estimate. (page) https://archive.nyu.edu/handle/2451/27234
- Figure "0.9% per annum" for the US mutual-fund industry is attributed to EGB by a search summary (snippet only, not confirmed in the paper). A "1.4% a year" figure is attributed to Brown & Goetzmann, and "about 70 bp" across studies (snippet only). https://archive.nyu.edu/bitstream/2451/27418/2/S-AM-00-08.pdf
- Brown, Goetzmann, Ibbotson, Ross (1992), RFS 5:553-580 and Carhart, Carpenter, Lynch, Musto (2002): survivorship bias can grow with sample length when survival depends on multi-period performance (snippet only). https://pages.stern.nyu.edu/~jcarpen0/pdfs/CarhartCarpenterLynchMusto.pdf
- Stock-level delisting bias: Shumway (1997, J. Finance 52:327) says missing CRSP delisting returns for negative-reason delistings are large; Shumway & Warther (1999, J. Finance 54:2361) estimate -55% for missing performance-related Nasdaq delisting returns; after correction "no evidence" of a Nasdaq size effect (snippet only). https://econpapers.repec.org/RePEc:bla:jfinan:v:52:y:1997:i:1:p:327-40 , https://econpapers.repec.org/RePEc:bla:jfinan:v:54:y:1999:i:6:p:2361-2379
- I found no peer-reviewed number for the bias from using today's S&P 500 members in a stock backtest. (unconfirmed) One trading blog gives a made-up 12% vs 6% example (snippet only). https://bookmap.com/blog/survivorship-bias-in-market-data-what-traders-need-to-know

## 4. Look-ahead bias sources

- SEC EDGAR (page): accepts filings 6:00-22:00 ET weekdays; submissions starting after 17:30 ET are "disseminated the next business day"; Forms 3/4/5 cutoff 22:00 ET; daily indexes update from about 22:00 ET; limit 10 requests per second; scripts must declare a User-Agent with contact email. https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data
- Filing date vs acceptance time (snippet only): Reg S-T Rule 13(a): after 17:30 ET is deemed filed next business day; example 10-Q accepted 18:04 ET on 8 May 2018 had filing date 9 May; Form 144 later added to the 22:00 exceptions; a 2025 change for fee-related filings is unconfirmed. https://www.sec.gov/page/edgar-how-do-i-determine-status-my-filing , https://www.sec.gov:443/files/rules/final/2023/33-11159.pdf
- GDELT 2.0 (page): Events and GKG "now update every 15 minutes"; the Mentions table records "the timestamp the article was published"; 2.0 files start 19 Feb 2015. DATEADDED semantics not stated on this page. https://blog.gdeltproject.org/gdelt-2-0-our-global-world-in-realtime/
- NYT Archive API (page via aggregator): one JSON per month from 1851, metadata only, no body; the page says nothing about revisions of archived months; cited limit 5 requests/minute and 500/day. `pub_date` semantics not found. (unconfirmed) https://jentic.com/apis/nytimes.com/archive.md . The NYT developer site itself was blocked to my fetch tool.
- Guardian Content API: semantics of webPublicationDate, firstPublicationDate, lastModified not confirmed (official docs blocked to my fetch tool; aggregator page silent). (unconfirmed) https://open-platform.theguardian.com/documentation/search
- Restated fundamentals and other restatement points: no primary source fetched. (unconfirmed)
- Closing price includes the closing auction on HKEX for CAS stocks (see section 2 page). For US, no source fetched on the closing auction.
- Time-zone gap: 16:00 US Eastern close is 04:00 or 05:00 HKT depending on US daylight saving, versus HK open at 09:30 (my arithmetic, not sourced).
- Fill convention (snippet only): common fix is to decide on the last closed bar and fill at the next bar's open; multiplying a bar-t signal by bar-t's own return is a common bug; NautilusTrader says bar ts_event may mean open or close depending on the data source. https://nautilustrader.io/docs/latest/concepts/backtesting/bar-execution/ , https://dev.to/matthieu_david_9bfe2b8e4f/your-backtest-is-lying-to-you-6-ways-future-data-leaks-in-5d9m
- Purge and embargo (snippet only, secondary): from López de Prado, Advances in Financial Machine Learning, ch. 7; embargo applies after the test set, purging on both sides. https://en.wikipedia.org/wiki/Purged_cross-validation

## 5. Data validation practice

- Qlib `scripts/check_data_health.py` (page, read from source): per instrument it checks (1) null counts per column vs `missing_data_num` (default 0); (2) large step changes, max absolute period-over-period % change for open/high/low/close above 0.5 (50%) and volume above 3 (300%) by default; (3) required columns open/high/low/close/volume; (4) `factor` column missing or all null; plus lowercase feature-directory names. Reader noted two code bugs (KeyError when factor column absent; first condition repeats the step-change result). https://raw.githubusercontent.com/microsoft/qlib/main/scripts/check_data_health.py ; docs: https://qlib.readthedocs.io/en/latest/component/data.html
- Brownlees & Gallo (2006), "Financial econometric analysis at ultra-high frequency: Data handling concerns," CSDA 51:2232-2245: proposes an outlier-removal method for NYSE TAQ; finds coefficient differences are larger between dirty and clean series than among different cleaning algorithms. (snippet only) https://econpapers.repec.org/RePEc:fir:econom:wp2006_03 . The rule itself could not be read (PDF unreadable). From memory, unconfirmed: it drops a price if it lies outside a window of k neighbours' trimmed mean by more than 3 trimmed standard deviations plus a granularity parameter gamma.
- Barndorff-Nielsen, Hansen, Lunde, Shephard (2009), Econometrics Journal 12(3):C1-C32, "Realized kernels in practice: trades and quotes," has a data-cleaning section; a citing paper describes median of same-timestamp trades and dropping zero prices (snippet only, not confirmed against the original). https://scholar.harvard.edu/sites/scholar.harvard.edu/files/RKpractice-ECTJ.pdf
- yfinance's own repair detects 100x errors and dividend/split inconsistencies (section 1).
- pandera: DataFrameSchema + Column + Check for pandas; statistical hypothesis checks via `pandera[hypotheses]`. (page) https://pandera.readthedocs.io/en/stable/ . Great Expectations: Python library, docs version 1.24.1; the landing page did not define expectations. (page) https://docs.greatexpectations.io/docs/home/
- Winsorization (snippet only, generic): per-date cross-sectional winsorization is common; one tool defaults to 0.5%/99.5%; 1%/99% described as a common default; one source advises against winsorizing returns for tail-risk measures. https://skfolio.org/generated/skfolio.preprocessing.CSWinsorizer.html , https://www.luxalgo.com/library/concept/winsorization/ . A 1%/99% convention in the anomalies literature: not confirmed for any specific paper. (unconfirmed)
- Hou, Xue, Zhang, "Replicating Anomalies" (RFS 2020): with microcaps mitigated (NYSE breakpoints, value-weighted), 65% of 452 anomalies fail |t| >= 1.96, 82% fail at 2.78; microcaps are about 3% of market equity. (snippet only) https://www.nber.org/papers/w23394.pdf

## 7. Storage and engineering patterns

- Qlib: `dump_bin.py` converts CSV/Parquet to `.bin`; layout `calendars/`, `instruments/`, `features/<code>/<field>.<freq>.bin`; inputs need open, close, high, low, volume, factor. (page) https://qlib.readthedocs.io/en/latest/component/data.html
- zipline bundles: separate asset DB, bcolz daily bars, SQLite adjustments (page). https://zipline.ml4trading.io/bundles.html
- ArcticDB: local LMDB (`lmdb://`) or S3/Azure; every write/append/update creates a new version; `as_of` time travel by version or datetime; snapshots protect versions; `prune_previous_versions` frees space; `append` requires new rows after existing data; `update` overwrites a contiguous date range; static schema by default. (page) https://docs.arcticdb.io/latest/
- DuckDB: `COPY ... TO ... (FORMAT parquet, PARTITION_BY (year, month))` writes `year=2022/month=11/` folders; `read_parquet(..., hive_partitioning=true)`; filters on partition keys are pushed down; PARTITION_BY takes column names only.
